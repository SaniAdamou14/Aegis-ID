# IAM-001 — Privileged accounts without strong MFA registered

- **Severity**: Critical (High if the account has phone-based MFA only)
- **CIS Microsoft 365 Benchmark**: 1.1.1
- **MITRE ATT&CK**: T1078.004 — Valid Accounts: Cloud Accounts

## Logic

For every user assigned at least one privileged directory role (Global
Administrator, Privileged Role Administrator, Security Administrator,
Exchange Administrator, SharePoint Administrator, User Administrator,
Application Administrator, Cloud Application Administrator, Authentication
Administrator, Helpdesk Administrator):

- If the user has no strong MFA method (FIDO2, Microsoft Authenticator,
  Windows Hello for Business, certificate-based auth) registered, a finding
  is produced.
- If the only registered methods are SMS or voice call, the finding is
  raised at `High` instead of `Critical`, with an explicit note about the
  weakness of phone-based MFA.
- If the account is configured as a break-glass account, it is still
  evaluated but the resulting finding is tagged `expected exception` and
  excluded from the posture score.

## Known false positives

- Accounts with a strong method registered but temporarily suspended will
  not be flagged by this control — deprovisioning is out of scope for v1.
- Role assignments made through nested group-based role assignment are not
  yet resolved in the snapshot model; only direct assignments are captured.
